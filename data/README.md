# Data

## Sample policy corpus (`data/sample_documents/`)

Five synthetic but realistic PDFs generated by
`python scripts/make_sample_documents.py`. Page numbers are stable, which makes
page-level citations testable.

| Document | Pages | Example facts |
| --- | --- | --- |
| `Employee_Handbook.pdf` | 6 | 24 days annual leave, 9:30-18:30 working hours, 60-day notice |
| `Remote_Work_Policy.pdf` | 4 | two remote days per week, INR 25,000 home-office allowance, cross-border approval |
| `IT_Security_Policy.pdf` | 5 | 14-character passwords, one-hour incident reporting, 90-day privileged rotation |
| `Expense_and_Travel_Policy.pdf` | 4 | INR 6,000 metro hotel limit, 15-day receipt submission |
| `Product_Support_SLA.pdf` | 4 | 15-minute P1 response, P2 escalation after 4 hours |

Facts are intentionally spread across pages so retrieval mistakes are visible in
the evaluation, and a few topics (security reporting, approval) appear in more
than one document so the system has to rank the right one.

## Uploads (`data/uploads/`)

Runtime only, gitignored. Files are stored as `<document_id>.pdf`; the original
name lives in the database and in every citation.

## Evaluation set (`data/evaluation/questions.jsonl`)

One JSON object per line:

| Field | Required | Purpose |
| --- | --- | --- |
| `id` | yes | Stable identifier for reports |
| `question` | yes | Asked through the real `/chat` pipeline |
| `gold_document` | yes | Expected source file name |
| `gold_pages` | no | Expected page numbers (1-based) |
| `expected_keywords` | no | Facts that must appear in the answer |
| `reference_answer` | no | Human answer for comparison |

To extend the set, append a line and re-run `python scripts/evaluate.py`. Keep
questions phrased differently from the source text so the set measures semantic
retrieval rather than string matching.
